## 1. What this is

- A browser game: you fly a small light (the Wisp) through side-scrolling pixel-art courses, collect Sparks, and build a **Chain** of cards whose effects fire in order. Roguelite run of three maps. Played on a phone in landscape (the owner's device is a Pixel 10).
- Names: **Orbix** = repository and deployment; **Wispbound** = title shown to players; **Emberwing** = name in older comments. Do not rename anything.
- Repository root: `F:\Vibecode\Orbix` (Windows 11). Git remote `MocanuMarius/orbix`, branch `main`.
- Public game: https://mocanumarius.github.io/orbix/ , published from branch `gh-pages` by the release tool only (section 5). Pushing `main` does not deploy.
- No build step. The game is plain ES modules, CSS and assets under `dist/`. Tests use Node's built-in runner. Node 24.
- Local server: `node server.mjs` (port 4173; launch name `orbix` in `.claude/launch.json`). Game at `http://localhost:4173/game.html`, design-lab review pages at `http://localhost:4173/design-lab/index.html`.
- Read `AGENTS.md` first (shared rules; `CLAUDE.md` imports it). Then this file. Then `docs/overnight-plan.md` only for history: its top sections are superseded by sections 2, 3 and 9 here.

## 2. How to work (standing rules from the owner)

**Roles.** The coordinator (Claude Fable 5.2, or the equivalent top model) plans, decides, writes briefs, reviews, commits and releases. Workers are subagents: **Sonnet by default**; **Opus only** for render-loop/performance work, tutorial flow, save logic or after a Sonnet worker failed (say why); Haiku for checklist chores. Workers start with no history: every brief states the goal, the decisions already made, the files they own, the files they must not touch, the checks, and the rules below.

**Every worker brief must include:** never commit, push or release; never `git stash`, `git clean`, `git reset --hard`, `git add .`, `git rm`; never kill browser or emulator processes it did not start; never use the owner's real Chrome profile (throwaway profiles only); never delete or modify untracked files (they are the owner's local art, studies and captures); send a "safe point" message listing every file touched when a shippable step is done.

**Coordinator after each safe point:** run the touched tests, look at the screenshots, `git add` the explicit file list, commit, `git push origin main`, release under a NEW label, read the release log (section 5). Never `git add .`.

**Thrift.** The owner prefers slow and cheap over fast. One worker at a time by default; a second only when files do not overlap. Tight briefs, short replies. Text checks before screenshots. Replies to the owner are terse (the "caveman" style is on): short fragments, no filler, full sentences only for warnings and irreversible actions.

**Work the backlog continuously.** Build what needs no decision without waiting. Ship each finished piece at once.

**When to ask the owner (only these):** anything involving money, billing, accounts or paid services (always ask first, never open such pages speculatively); deleting files outside the lists approved in section 9; a new design direction not covered here. For looks the owner said "lead and push, I'll review in game": decide, ship, report. When a real choice must be put to the owner, give one question at a time with a recommendation.

**Reviewing looks.** The owner can open previews on this PC. In-flight visuals are reviewed as **videos of real gameplay in variants A/B/C/D**, large, with a zoomed clip, picked by a version code (`docs/design-versions.md`). Use `scripts/variant-clips.mjs` (section 7) and a page under `dist/design-lab/` laid out like `dist/design-lab/strip.html`. After the owner picks, remove the losing variants and their switch ("no backups").

**UI rules (every menu change).** Look at screenshots at 890×400, 924×308 and 740×333 before release and say what you saw. No scrolling where content fits (at 308 px height one pinned scroll area at most); nothing clipped; equal heights in a row; one primary action; one way out per screen; **use the top bar** (never a row holding a lone Back/Close button or a one-line note); picks are **tap to select, tap again to take** (`dist/tap-pick.mjs`), no per-item Choose buttons; linked glossary words get a dotted underline only (never a highlight box); no negative numbers, no "wallet"/"reserve" wording; no tap highlight or sticky hover on touch (`dist/touch-clean.*`).

**Game design rules.** Never require reading during flight (text only while the simulation is stopped). No pointed arrows. Pixel art in whole-pixel multiples, no grain. **An effect lives on a card or on a Chain slot** (a card's effect exists only while mounted; whatever it builds up is stored on the card and shown on its face as a badge; Inscriptions are written on slots). The only exception is the start-of-run Wisp stat (section 6), shown as a chip. No arbitrary caps or nerfs; crazy combos are welcome. Spark Meter cap 100. Sparks round up per firing. Boosts and Inscriptions never multiply Stored Sparks or permanent growth. Events flow left to right; only Timers return to the first slot. All music is generated by code (no audio files, no downloads).

**Phone testing is automated.** Never ask the owner to play, measure or plug in a phone. Use the Pixel 10 emulator (section 7).

**Machine safety.** Do not change Windows settings. Downloads only from official hosts already approved (Google for the Android SDK). No credentials in files.

## 5. Releasing (the only way to publish)

```
node scripts/release.mjs all --source <commit> --version <label> --allow-unlisted dist/offline-list.js --publish > work/<label>-run.log 2>&1; echo "exit $?"
```

- Run it in the background (it takes 3–5 minutes) and **read the log**: success is the two lines `[release <label>] live {...}` and `[release <label>] verified {...}`. The shell's own exit status is not enough.
- `<commit>` must already be pushed to `origin/main`.
- **The label must be new.** If `work/release-<label>` exists the tool reuses that old prepared build ("reusing prepared artifact" in the log). Check with `[ -d work/release-<label> ]` first. Labels used so far include everything in section 10.
- `--allow-unlisted dist/offline-list.js` is always needed (the Update button reads that file, which is deliberately not cached).
- Removing files that an earlier release cached: add `--allow-dev-page-removal` for developer pages and `--allow-graph-removal dist/<path>` for each other file.
- The tool compares saves made by the previous public release with the new build and stops on any undocumented change ("cardsSave: only documented save changes"). If the change is intended, add a narrow rule in `classifySaveDiff` in `scripts/release.mjs` (see the existing dated examples) and release under a new label.
- "public exact bytes" failing right after `live` is usually CDN lag: run `node scripts/release.mjs verify --version <label>`.
- "focused tests" failing: read `work/release-<label>/artifact-tests.log`. A random-seed test has failed once (`tests/tutorial-starter-routing.test.mjs`); fix the test, new label.
- Never force-push or replace `gh-pages` by hand.
- Players update with Settings → **Update now** (unregisters the offline worker, clears caches, reloads; saves are kept). The automatic update is unreliable on mobile data.
- Old saves: the owner does not care about saves at this stage, but the release check still guards them; add rules rather than bypass.

## 6. The game as it is now

**Run.** Three maps of 15 / 15 / 17 rows; about 28 flights, 11 Rests, 27 card rewards per full run. Stops: flights, Elites, a Guardian (boss) ending each map, Rests (3 guaranteed + 1 optional per map), Scribe stops, chests, events. The run ends after the third Guardian.

**Chain and cards.** Up to 5 slots. A card fires on its trigger; effects resolve left to right. Player-facing triggers (7): **Collect, Lift, Pulse, Delivery, Overfill, Finish, Skim**. Roles: **Passive, Boost, Repeat**. Other face words: Start, Rest, Flare, Turn, Timer. "Save" was removed as a trigger. Display names come from `dist/card-trigger-labels.mjs`; internal keys are pinned by `tests/fixtures/card-trigger-keys.json`.
- A card face has two lines (`dist/card-face-lines.mjs`): trigger icon + one word, then the effect in a few words. Caps and fine print live only in the "?" help / card detail panel. A face never scrolls.
- Growth is stored on the card (`tally`, `seedBonus`, `eatenGrowth`…) and shown as a badge on the picture (`cardGrowthBadge` in `dist/card-ui.mjs`).
- Catalogue: `dist/card-catalog.mjs`; engine: `dist/skill-cards.mjs` (misnamed: it is the whole card engine), `dist/card-engine.mjs` (declarative timer/engine cards), `dist/flight.mjs`, `dist/model.mjs`.
- 113 released cards, all proven by `scripts/balance/card-works-audit.mjs` (`tests/card-works.test.mjs`; `CARD_WORKS_FLIGHTS=2` runs real flights; table in `outputs/balance/card-works.md`).
- Notable rules: Devour cards (Black Hole, Dream, Devourer, Ember Feeder) eat a neighbour and announce it (departure warning, "Devoured: X" on rewards); Growth Ring, Wind Feather and Deep Vessel are `permanent` and cannot be eaten. Wind Feather: +1% speed per cleared flight while mounted, max +10%. Growth Ring: +1 max Spark per cleared flight while mounted. Growth Seeds merge into one card. Second Look (Rare, Passive): while mounted, re-roll one offered card per card reward into the same rarity. Twin Mark on a Boost applies it twice (intended). Curtain Call fires the slot-1 card's printed Sparks three times at Finish, ignoring that card's condition (intended).
- **Flare** (white triangle pickup; internal ids still say "flash"): 8 s, a Pulse every 2 s plus a Luminance bonus; at least one per flight on rows 1+.

**Inscriptions** (`dist/inscriptions.mjs`, spec `docs/inscriptions.md`): written on a Chain slot, one per slot. 18 ordinary ones from Scribes (two offers, `dist/inscription-write.mjs`), 6 Scribes per run. Five rare chest/wager ones: Far Lens, Quick Lens, Mending Wick, Toll Stamp (chest finds), Lamplighter's Seal (wager). `dist/inscription-on-card.mjs` gives a true sentence for every Inscription × card pair, shown in the card detail panel, on the Scribe preview ("no effect on this card" in red) and as a warning mark on the Chain tab. Glyphs: 24×24 two-tone, `scripts/build-inscription-glyphs.mjs`.

**Start of run** (`dist/start-bonus.mjs`): "Choose your start" shows three random offers, each drawn with equal chance from starter cards / ordinary Inscriptions (written on slot 1) / Wisp stats; Lift Guide is always mounted too. Five starter cards, each teaches a trigger with a wordless in-flight cue (`dist/starter-cues.mjs`) and pays for doing it: Lift Guide (Lift on the cue +1 Spark), Skim Line (Skim +12 Sparks), Pulse Reader (sends its own Pulse every 8 s), Courier Cord, Meter Mark. (Finish Flag was a sixth; the owner had it retired on 19 November, `noflag-1`.) Wisp stats (stored as `run.wispBonus`, chip on the Deck screen): Collector reach +20%, Max Meter +5, +1 heart, Luminance +10%, +10 Stored Sparks, Collector recovers 20% faster.

**Economy.** Stored Sparks are the currency (about 830 earned per full run when every flight is cleared; `scripts/balance/economy-run.mjs`, `outputs/balance/economy.md`). Card offers roll **per offered card: 5% Rare, 0.5% Legendary**, flat all run; a Guardian's pack reserves slot 1 for a Legendary, an Elite's for a Rare. Workshop at Rest (`dist/card-workshop.mjs`): Improve 15, Refill, Forge base 15 / 40 / 150 by rarity; **each Forge or Evolve of a tier doubles that tier's price for the rest of the run**, and Evolve costs the current Forge price of the rarity the card becomes. Chests: the chest's find (if its site has one) plus a choice of Stored Sparks or a surprise card. Events: pick 1 of 2 outcomes (`dist/stop-screen.mjs`).

**Screens** (all in the parchment house style): Deck (`dist/ui/deck-screen.mjs`: Chain / Deck / Triggers tabs; Chain tab simulates each trigger, including a Lift with its cost; Timer chains show an hourglass), card detail panel, Choose 1 Card (`dist/flight-reward-ceremony.mjs`), flight rewards with a slot-style tally (`dist/reward-tally.mjs`), Rest and Workshop, Scribe, event/chest stops, lesson sheets (`dist/tutorial-coach.mjs`, `dist/tutorial-visuals.mjs`, `dist/onboarding.mjs`), Settings (Update now, Fullscreen, Install, Show FPS). In flight: Chain strip top centre, hollow frames, white flash with `+N` below the firing card (`dist/chain-strip.mjs`, approved as `v1.2-strip`). The Collector's cord is the original bow drawn while towing (`drawCollectorGrip` in `dist/capture-art.mjs`): rope, whip and elastic variants were reviewed on 18 November, the elastic one shipped as `cord-1` and the owner then rejected it in game, so it was reverted (`cord-2`) and its code removed. Do not reopen the cord unless the owner asks.

**Tutorial**: First Light practice, Edition 5 (`dist/practice-course.mjs`, `dist/practice-route.mjs`). It is still a non-card run internally (section 9, P6).

**Rendering.** Flight is Canvas 2D (`dist/wisp-renderer.mjs`) with a WebGL2 light compositor (`dist/light-gpu.mjs`, default on; `?gl=0` is the fallback for devices without WebGL2 and must stay). Vendored Pixi/Three were unused and have been deleted.
