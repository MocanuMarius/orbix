# Design versions

Every proposed look gets a code. The user approves or rejects by code ("`v1.0-pause` looks good"), and only an approved code is built into the game. Previews live in the design lab: `http://localhost:4173/design-lab/index.html` (source in `dist/design-lab/`, rendered with the production stylesheets and icons; not part of the offline release graph).

Code format: `v<major>.<minor>-<surface>`. `v0-<surface>` is always what ships today. A requested change to a proposal bumps the minor (`v1.0` → `v1.1`); a different direction bumps the major.

## Rules

- Add a row here whenever a look is proposed; update Status when the user answers (Approved → Implemented in `<commit>`, or Rejected with the reason).
- A preview must use real production renderers/styles where possible, and include the current look (`v0`) for comparison.
- **Standing approval for reskinning (2026-11-16).** The user: "we should fix all menus with the kit and theme, including main menu, tidy them up… no need for me to confirm, just adjust and push them." Applying the approved kit (`v2.5-theme`) to an existing menu, and tidying it, needs no preview or verdict; a runner pushes it once checks pass. New behaviour or a new look still gets a code and a verdict.
- **Prune the lab.** (User, 2026-11-17.) Once a topic is decided or no longer needed, remove it from the lab's list; this file keeps the record. The lab lists only open work plus the style kit. Pruned on 2026-11-17: pause menu, Settings, icons, card wording, how cards fire, earlier Deck looks.
- **One topic at a time in the lab.** The lab has a Topic dropdown. A decided topic shows only its approved look, with older looks behind History. Requested by the user on 2026-11-16.
- **The component kit sets the tune.** Whenever the user approves a look, move its new pieces to Approved in the kit (the `*-theme` entry and the kit sheet in the design lab) in the same turn, and build later screens from approved pieces first. Requested by the user on 2026-11-16.
- Approval of a code authorizes building exactly that look. Anything that drifts from it during implementation comes back as a new code.
